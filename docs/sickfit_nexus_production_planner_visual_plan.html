SickFit Nexus · Production & Restock

Visual Production Planner and Run Simulator

A repository-aware implementation plan for turning the existing Production page into a visual decision-support workspace that shows what to make, how much to make, when it should arrive, what inventory risk remains, and what the team should do next.

React + TypeScript + Vite Supabase Postgres Recharts already installed Non-destructive simulation Reusable production templates

Product decision

The Production Planner should be a decision layer between inventory risk and creation of a Manufacturer PO.

Recommended direction

Do not make the planner a spreadsheet with prettier numbers.

The primary output must be a visual story: current inventory trajectory, projected stockout, planned production arrival, recovered coverage, manufacturer capacity, cost, and the operational steps needed to execute the run. Tables remain available for detail and editing, but graphs should explain the plan first.

One shared simulation result

Charts, recommendations, summary cards, and SKU tables must all render from the same versioned result object so totals cannot drift.

Baseline versus proposed

Every visual should make the difference between “do nothing” and “run this plan” immediately understandable.

Explainable recommendations

Recommendations should identify the trigger, operational impact, proposed action, and which chart or SKU supports the conclusion.

Visual-first planner experience

Suggested desktop layout for the Simulation Results view. The recommendation rail stays visible while the user explores charts and SKU details.

Minimum visual package

These visuals are required for the first complete version. They should not be replaced by a table-only implementation.

Visual acceptance gate

1. Inventory projection timeline

Multi-line or composed chart showing baseline inventory, proposed-plan inventory, safety stock, zero-stock threshold, demand, and planned receipt dates.

Primary decision chart

2. Before vs after coverage

Grouped bar chart comparing days of supply before the run and after the run by SKU, family, category, or selected group.

Shows improvement

3. Production schedule timeline

Gantt-style visual for approval, purchase order, manufacturing, quality check, packaging, freight, and receiving milestones.

Shows feasibility

4. Capacity utilization

Stacked bar or progress/gauge view of available, previously committed, newly proposed, and remaining capacity by manufacturer and week.

Shows constraints

5. SKU risk matrix

Heatmap or sortable matrix plotting stockout urgency against business impact. Clicking a cell filters the SKU table and recommendations.

Shows priorities

6. Cost and quantity mix

Donut or stacked bar view of planned units and estimated cost by category, product family, or manufacturer.

Shows allocation

Optional second-pass visuals

Scenario comparison

Compare Base, Conservative, Recommended, and Aggressive plans across cost, stockouts, coverage, and capacity.

Inventory waterfall

Explain how on-hand inventory becomes ending inventory after allocations, demand, inbound orders, and the proposed run.

Recommendation impact

Show how applying a recommendation changes cost, stockout count, arrival gap, or days of supply before saving the change.

End-to-end planner workflow

The simulator remains non-destructive until a user approves and converts the plan.

1Start planBlank, template, reorder queue, or duplicate past run.
2Set goalRestock, launch, seasonal build, emergency, or custom.
3Choose inputsHorizon, manufacturer, target date, demand, and buffers.
4Build runSelect SKUs, quantities, specs, packaging, and costs.
5SimulateGenerate a versioned, read-only result snapshot.
6Review visualsInspect charts, risks, conflicts, recommendations, and detail.
7Take actionSave, revise, approve, split, export, or convert to Manufacturer PO.

Simulation rules and outputs

Use deterministic, testable calculations first. Recommendations should be explainable and should not require an AI service for the MVP.

Core daily projection

projectedAvailable[day]
= startingOnHand
- startingAllocated
- confirmedDemandThroughDay
- forecastDemandThroughDay
+ existingIncomingReceivedByDay
+ proposedProductionReceivedByDay

Calculate this by SKU for every day in the selected horizon, then aggregate for category and portfolio charts.

Required derived values

  • First date below safety stock
  • First stockout date
  • Number of stockout days
  • Inventory gap before proposed receipt
  • Days of supply before and after
  • Suggested, planned, minimum, and rounded quantities
  • Capacity used and capacity conflict
  • Estimated line and plan cost
  • Slow-moving and overproduction flags

Simulation result contract

interface ProductionSimulationResult {
  simulationId: string;
  simulatedAt: string;
  horizon: { startDate: string; endDate: string; days: number };
  summary: {
    totalUnits: number;
    estimatedCost: number;
    stockoutsBefore: number;
    stockoutsAfter: number;
    capacityUtilizationPercent: number;
    targetArrivalDate: string | null;
    feasibleArrivalDate: string | null;
  };
  dailyPortfolioSeries: Array<{
    date: string;
    baselineAvailable: number;
    proposedAvailable: number;
    safetyStock: number;
    forecastDemand: number;
    existingIncoming: number;
    proposedIncoming: number;
  }>;
  skuResults: ProductionSimulationSkuResult[];
  capacitySeries: CapacityBucketResult[];
  scheduleMilestones: ProductionMilestone[];
  costMix: ProductionMixPoint[];
  riskMatrix: ProductionRiskPoint[];
  recommendations: ProductionRecommendation[];
}

Implementation phases

Each phase should leave the existing Production and Purchase Order workflows functional.

Phase 1

Foundation and schema

Add types, migration, CRUD services, routes, and a basic plan list/detail shell. No simulation writes to inventory.

  • Create plan/template/simulation tables and policies.
  • Add domain types and service methods.
  • Add navigation while retaining current Manufacturing Orders access.
  • Support blank plans and plans created from reorder recommendations.
Phase 2

Deterministic simulation engine

Build pure TypeScript calculations and tests before connecting complex UI.

  • Daily SKU projections and aggregation.
  • Lead time, receipt, safety stock, MOQ, and quantity increment handling.
  • Capacity conflict and stockout-gap calculations.
  • Rule-based recommendations with traceable reason codes.
Phase 3

Visual plan builder and results

Create the main planner workspace, required charts, linked interactions, tooltips, and recommendation rail.

  • Baseline versus proposed inventory chart.
  • Coverage, schedule, capacity, risk, and mix visuals.
  • SKU table as supporting detail below the visuals.
  • Responsive and accessible chart fallbacks.
Phase 4

Templates and scenarios

Add reusable production recipes and side-by-side scenario comparison.

  • Create/edit/duplicate/archive templates.
  • Apply a template without locking the plan.
  • Save multiple simulation versions.
  • Compare cost, coverage, stockouts, and capacity visually.
Phase 5

Approval and Manufacturer PO conversion

Convert only an approved plan, preserving source snapshots and manufacturing specifications.

  • Readiness checks and blockers.
  • Convert one plan to one or more Manufacturer POs.
  • Link generated PO back to plan and simulation version.
  • Do not create inventory events until existing receive-inventory workflow runs.
Phase 6

QA, polish, and operational rollout

Reconcile every chart with table totals and protect existing Production workflows.

  • Unit and integration tests.
  • Mobile chart behavior and empty states.
  • Performance with large SKU sets.
  • Audit history, exports, documentation, and seed/demo data.

Definition of done

The following criteria keep the planner operational, visual, and trustworthy.

  • A user can create, edit, simulate, save, approve, and convert a production plan.
  • Simulation does not mutate inventory, allocation, capacity, or purchase-order data.
  • The hero inventory chart clearly compares baseline versus proposed outcomes.
  • Safety stock, zero inventory, receipt dates, target arrival, and stockout gaps are visible.
  • Coverage, schedule, capacity, risk, and production mix are shown graphically.
  • Tables support chart detail rather than replacing required visuals.
  • All visual and textual outputs reconcile to one stored simulation result.
  • Recommendations are explainable and show trigger, impact, action, and evidence.
  • Plan edits mark simulation output stale until re-run.
  • Templates create editable plan copies and support manufacturing defaults.
  • Multiple named scenarios can be compared visually.
  • Capacity conflicts and readiness blockers are obvious before approval.
  • Only approved, current simulation versions can convert.
  • PO conversion is idempotent and preserves plan/simulation lineage.
  • Receiving a Manufacturer PO remains the only path that adds real inventory.
  • Charts have accessible labels, legends, summaries, and non-color status cues.
  • Mobile layout remains usable without hiding critical information.
  • Vitest and production build pass.
  • Existing Production, Inventory, PO, Dashboard, and Reports behavior is preserved.
